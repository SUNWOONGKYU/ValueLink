# DB 복구 전략 심층 연구 결과 (2026-06-11)

## ⚠️ 핵심 발견 — 직전 세션 전제가 틀렸다

직전 진단의 c안 전제는 "부재 8테이블을 **schema-v4-final.sql 기준** CREATE"였으나, 조사 결과:

1. **부재 8테이블 중 6개는 schema-v4-final.sql에도 없다**
   - 있음(2): `evaluation_requests`, `project_history`
   - 없음(6): `valuation_projects`, `support_cases`, `partner_referrals`, `deal_news`, `investor_watchlist`, `workflow_approvals`
   - 이 6개의 CREATE 문은 리포지토리 전체에 존재하지 않음 (`valuation_projects`만 docs 마크다운에 초안 1건)
2. **코드의 `valuation_results` 기대 형태는 어떤 스키마 파일과도 불일치**
   - 코드(5개 결과 페이지): 통합 `valuation_results` 테이블 + 메서드별 개별 컬럼 30+ (`company_name`, `valuation_date`, `shares_outstanding`, `wacc_components`, `fcff_projections`...) — `app/valuation-results/dcf/page.tsx:61-70`에서 명시적 select 확인
   - schema-v4-final.sql: 메서드별 분리 테이블(`dcf_results` 등 5개) — 코드가 안 씀
   - database/schema.sql(2/6): 통합이지만 `calculation_data` JSONB — 코드 기대 컬럼 없음
   - 실DB: `method` + `calculation_details` JSONB — 코드 기대 컬럼 없음
3. **결론: 코드가 유일한 스키마 진실 소스다.** "v4 재배포"라는 개념 자체가 성립 안 함 — 코드는 v4 스키마 파일 이후로도 진화했고, 그 스키마는 파일로 기록된 적이 없다.

## 사실 기반 (조사 출처)

- 스키마 파일: `database/schema-v4-final.sql`(41테이블, 2/7) = `supabase/migrations/20260209000001_schema_v4.sql` 동일본. RLS: `database/rls-policies.sql`, 트리거: `database/triggers-v4.sql`
- v4 `projects`: `user_id`·`accountant_id` 있음, `customer_id` 없음, PK `project_id VARCHAR(50)` ← 코드 기대와 일치
- 코드 의존도: `valuation_results` 5파일(30+컬럼), `projects` 14파일, 부재 8테이블 17파일
- 구데이터(평가결과 25건)를 읽는 코드: **0건** — 데이터 변환 불필요
- `types/database.types.ts`: 스켈레톤만 존재(users 1개) → 타입 오류 ~240개의 원인. 실쿼리 파일들은 타입 미사용

## 최종 추천: c-수정안

**원래 c안과의 차이**: "schema-v4-final.sql 기준 CREATE"가 아니라 **코드를 역분석해 스키마를 새로 작성**해야 한다. v4 파일은 참고 자료일 뿐 그대로 못 쓴다.

### 실행 계획 (Track A 수정판)
1. 코드 전수 역분석 → 14테이블 코드-진실 스키마 SQL 작성 (`evaluation_requests`·`project_history`는 v4 파일 재사용 가능)
2. 구 `valuation_results`·`projects` → `_legacy` rename (25건+기존 데이터 보관)
3. 신규 스키마 적용 (CREATE + RLS + 트리거) — Supabase에 멱등 SQL 실행
4. `database.types.ts` 재생성 (supabase gen types) → 타입 오류 ~240개 해소
5. 잔여 타입 오류 수정 (깨진 import 1 + tsconfig) → `next build` 통과
6. Vercel `CRON_SECRET` 공백 수정 → 재배포
7. 검증: 별도 Verification Agent가 실브라우저 클릭 테스트 (E2E + 결과 페이지 5종)
